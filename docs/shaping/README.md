# Feature shaping

Define a feature before adding scope that changes user behaviour, external access or runtime boundaries.

Each document states:

- The problem and users.
- The scope and expected behaviour.
- What stays outside the feature.
- Data and access implications.
- Acceptance checks.
- Unresolved questions and implementation status.

Describe current behaviour separately from proposals. A document does not approve a feature or establish that its acceptance checks pass.
